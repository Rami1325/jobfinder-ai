### Phase 25 — the landing is its own route (2026-09-06)

- **`/` OWNS ITS SHELL AND ITS PALETTE, and that is what makes the redesign safe.** It used to sit inside `MarketingLayout` with `/scan` and `/privacy`, sharing that layout's header, its `.paper` token scope and its aurora. `/privacy` still does, unchanged; `/scan` became a redirect to the sign-up door in Phase 30 / A2, so that layout now serves exactly one page. The landing is now a bare route rendering `LandingHeader` + `main` + its own footer inside a `.jobfinder-landing` wrapper — a THIRD token scope beside `.paper` and `.sheet`, same mechanism (re-declare `--bg` / `--ink` / `--line` / `--accent` on one subtree, so every Tailwind token utility underneath re-resolves by inheritance). Nothing in `components/landing/*` or in that CSS block can reach another route, and a browser check asserts `/scan` and `/app` mount zero `.jobfinder-landing` elements. Reusing `MarketingLayout` would have meant a `pathname === "/"` branch inside a component two routes depend on.
- **THE LANDING IS DARK BY DEFAULT AND IT MUST NOT WRITE THAT DOWN.** `useLandingTheme` resolves "explicitly saved, else dark" — where `useTheme` (the app's hook) resolves an ABSENT preference from the operating system, which would land a visitor on a light desktop in the pale composition they never asked for. While nothing is stored the hook also mirrors `dark` onto `<html>` for the LIFETIME OF THE LANDING ONLY (so the document scrollbar and `theme-color` agree with the page) and reverts on unmount; that revert is the whole reason the mirror is honest. Verified in the browser: dark on `/`, `light` handed straight back on navigating to `/app`, `localStorage.theme` still null throughout. A tap on the control IS an explicit choice and IS persisted — and unlike `useTheme.toggle` it never CLEARS the key when the new value matches the system, because doing that here would drop the visitor back onto the landing's dark default the instant they chose light on a light machine, i.e. the control would appear to do nothing.
- **The star sculpture is `lib/starfield.ts` — a seeded 3D formation, Canvas 2D, ~1450 particles.** Four things in it are load-bearing. It is a CLASS driven from a ref, never React state, because a `setState` per pointer event re-renders the landing at pointer frequency. Its geometry is SEEDED (`mulberry32`), so the sculpture is the same picture on every load and the static fallback is the same arrangement rather than a lookalike. Its draw order is sorted ONCE at build time by (halo, tint), because `fillStyle` re-parses a string on every assignment and that is the only genuinely expensive thing in a loop this size — sorted, a frame costs at most three assignments, and `globalAlpha` is a number and free. And compositing is the palette's job: `lighter` on the dark art direction so overlapping stars accumulate into a luminous nucleus, `source-over` with a quieter halo on the light one, which would otherwise bleach to white.
- **THE READING ZONE IS A DIMMER, NOT AN EXCLUSION, and the first version got that wrong in a way worth remembering.** The copy block is ~1040x500 CSS px on a 1440x900 hero, so a hard exclusion around it erased the entire formation and left what looked like debris in the corners. It dims to a 0.24 floor instead, and the composition keeps the centre quiet by putting the dense part of the sculpture somewhere else.
- **The nucleus is placed BELOW the copy, DERIVED from where the copy actually ends** (`zone.cy + zone.hh + 0.035h`, clamped), not at a fixed fraction of the hero. A constant was the first version and it fails on exactly the viewport that matters most: at 1366x768 the copy block sits ~200px lower relative to the hero than at 1440x900, and the brightest part of the formation landed directly behind the access-code line.
- **THE SCENE IS TALLER THAN THE HERO AND IS MASKED, NOT CLIPPED.** Held inside the section the composition read as a cropped photograph — the lower arms ended on a dead-straight horizontal line and the base wash stopped against the flat ground of the next section. `.lp-scene` runs **32% past** the hero, carries `.lp-space` with it, and dissolves over the overhang, so the arms thin out behind the following section's heading instead of being sliced. Three things make that work and each is a way it breaks: the bleed is a **FIXED RATIO, not a clamp**, because every position in `.lp-space` is a percentage of THAT box and a viewport-dependent bleed would slide the whole wash around (the stops are the hero-relative values divided by 1.32 — 116% becomes 87.9%, and so on, which is what keeps the composition identical to the one designed by eye); the scene sits at **`-z-10`** so it passes UNDER later sections' text rather than over it, which is also why the hero no longer carries `isolate` (a stacking context there keeps the whole hero, overhang included, painting above every later sibling); and **the landing root MUST be a stacking context** or that negative z escapes to the root element and paints behind the wrapper's own background — the entire sculpture disappears, on a green build. That last one happened; it was found by looking at the page, not by any check.
- **`Starfield.resize` takes the hero height SEPARATELY from the canvas height.** `unit` and the nucleus placement are measured against the hero; the overhang is only room for the arms. Sizing off the drawing surface would grow the sculpture and drag the nucleus down every time the fade region grew.
- **A concentration of 1px points is not a concentration.** The nucleus is two pre-rendered sprites drawn once per frame at the projected origin — where the density actually is — because at any honest per-particle alpha the centre read as slightly-denser dust. Glow sprites are pre-rendered per tint and drawn scaled; building a gradient per particle per frame, or leaning on `shadowBlur`, is how this becomes a slideshow.
- **Frames are not SCHEDULED, not merely skipped.** Offscreen (IntersectionObserver), a hidden document, `prefers-reduced-motion`, a coarse pointer, or the visitor's own Pause control each stop the loop entirely. Measured: with the scene scrolled out of view the canvas does not change at all. The pointer handler stores coordinates only and the frame resolves them against a CACHED rect, so there is no forced layout at pointer frequency; `dt` is capped at 50 ms so a restored tab cannot jump the ambient rotation.
- **THE POINTER IS TRACKED ON THE WINDOW AND NORMALISED AGAINST THE SCENE, NOT THE HERO.** Binding to the hero was right while the two were the same box, and became wrong the moment the scene overhung it — twice over. The lower third of the galaxy sits inside the NEXT section, whose content is on top and is not a hero descendant, and the scene layer is `pointer-events: none` and can never be a target; so moving over the visible lower arms fired `pointerleave` on the hero and eased everything to neutral. And the FIXED HEADER covers the hero's top 73 px without being a hero descendant either, so pointing at the top of the hero killed the parallax in exactly the same way. Measured before the fix: the same horizontal sweep moved the arms **27.9 px inside the hero and 2.9 px over the overhang**. The IntersectionObserver watches the SCENE for the same reason — watching the hero stopped the loop while up to 288 px of galaxy was still on screen.
  A consequence worth stating: normalising against the scene moves the neutral point from the hero's centre to the scene's, about two thirds down the hero, which is roughly where the nucleus sits. Resting on the bright knot is a better zero than an arbitrary one.
- **Measured, not asserted** (Playwright, 1440x900): the nucleus travels **26.3 px** between opposite hero corners and the band centroids up to 73 px, reaching 46% of the way at 45 ms and 87% at 200 ms — an exponential settle, not a snap. Under `prefers-reduced-motion: reduce` the travel is exactly **0 px** and the Pause control is not rendered at all. Paused, two frames 1.2 s apart are byte-identical and the pointer is inert.
  **These numbers replace an earlier 12.1 px / 33% / 85%, and the difference is a lesson about the probe rather than a change in tuning.** That measurement swept between opposite hero CORNERS, and the top corner is under the fixed header — which, before the pointer fix above, neutralised the scene. One endpoint of a corner-to-corner measurement was therefore not the corner at all. A probe that drives the product through its own surfaces inherits the product's bugs, and this one reported a number 2.2x too small without ever failing.
- **The Pause control is withdrawn when there is nothing to pause**, which is a different question from "is it animating right now" — reporting the latter would take the Resume button away the instant the visitor pressed Pause. It is hidden for a coarse pointer, for reduced motion, and when the 2D context is unavailable or lost.
- **The still CSS composition (`.lp-space`) is part of the design, not a placeholder.** With `getContext("2d")` forced to return null the page still paints a coherent dark space scene, renders the headline and every real link, mounts every section, and throws nothing — verified by driving it, not by reading the code.
- **The closing echo is a SEPARATE FILE with no loop in it** (`EchoCanvas`), and that separation is the point: it draws exactly one frame plus one per resize, so a second particle engine cannot be started here by accident. It is the same seeded sculpture at lower density, over the same `.lp-echo` gradient a context-less browser is left with.
- **Reduced motion zeroes the entrance DELAYS, not just the durations.** The global `prefers-reduced-motion` rule collapses `animation-duration` only, so the hero's 70-410 ms stagger still meant the headline was invisible for four tenths of a second for someone who asked for less motion. `.lp-in { animation-delay: 0s !important }` under that media query is what makes "reveal all content immediately" true. `Rise` (the section entrance) returns its children with no wrapper state at all under reduced motion, and falls back to revealing everything after 900 ms if `IntersectionObserver` never fires — a section left at `opacity: 0` because an observer did not initialise is the failure this page can least afford.
- **The template stage reads `TEMPLATE_IDS`; no sentence on the page counts the templates.** Twelve are reachable through a two-column button list from `lg` and a native `select` below it, and the PDF-only disclosure is per-template and sits beside the choice it describes. The stage reserves its box by A4 aspect ratio, so switching template crossfades inside a container that never resizes — measured at 584x826 before and after.
- **The large preview passes `mirror={false}` and that is a real decision.** `ResumeMiniature` derives RTL from the UI language and expects its caller to mirror the sheet, which is right for a gallery of thumbnails and wrong here: the demo CV is English, so the DOCUMENT is left-to-right whatever the interface is set to, and mirroring it would be exactly the "flipped screenshot called Hebrew" the design brief rules out.
- **check-mirrors 28 exists because this page shipped a raw key on its first pass.** Consolidating the old `faq` block into `landing.faq` left `t("faq.kicker")` behind and the section rendered the literal string "faq.kicker" as its eyebrow, with every other check green — check 8 is parity-only, 16 and 22 are scoped to the tailor namespace, and 9 is deliberately scoped to `AppLayout.tsx`. The namespace is read off the `useTranslation` BINDING, not guessed from the key's prefix: `footer` exists in both bundles, so a prefix table reported a key that resolves perfectly as missing. One identifier bound to two namespaces in one file is REFUSED rather than guessed — rename the second binder, the way `LandingHeader` does.
- **Copy claims were checked against the code, and two were corrected in the process.** The old FAQ said both exporters are single-column while the gallery showed two PDF-only layouts; the new answer states the fallback explicitly and the picker repeats it next to the selection. The competitor-price line is gone (pricing research is not part of a landing redesign, and there was no dated source). The section explaining the absence of testimonials is gone too — a page with no reviews on it does not need a footnote about not having reviews — and `TODO_SOCIAL_PROOF` in `locales/*/marketing.json` records where genuine quotes would go.
- **Measured at 1440x900, 1366x768, 768x1024, 390x844 and a 320 px stress width, in both languages**: no page-level horizontal scrolling at any of them, none at 200% zoom, one `h1`, a working skip link as the first tab stop, every anchor landing clear of the fixed header, and no interactive target under 44 px. Text contrast was measured on the running page in both themes and everything meets AA — `--ink-faint` on the light scope was **4.01:1** as first written and is 4.69:1 now, which is the one token whose first value would have shipped failing.

No OpenAI Sans (its licence for third-party use is not established; Inter Variable is already licensed and loaded, and the reference's restraint is mostly weight and tracking rather than a different family). No redesign of `/app`, `/scan` or any tool page. No deploy.
